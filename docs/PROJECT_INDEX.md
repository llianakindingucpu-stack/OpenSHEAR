## 🎯 项目定位（核心共识）

```
一句话：Agent 自主推理的基础设施层

核心价值排序：
  1. 自由 — 不受任何单一实体审查或关停
  2. 进化 — 网络能力随数据持续增长
  3. 透明 — 推理过程可审计
  4. 可用 — 质量不如商业模型，但够用
  5. 便宜 — 长期目标，不是第一版卖点

不是什么：
  ❌ 不是"比 GPT-4 便宜的去中心化推理"
  ❌ 不是"替代集中式大模型"
  ❌ 不是"网络即一个大模型"（技术上不成立）
```

## 📋 MVP 验证计划（4 周）

### Step 1：单节点验证（第 1 周）

```
目标：验证 7B 模型在可验证任务上的推理质量

任务：
  ☐ 部署 Qwen2.5-Coder-7B（INT4 量化，vLLM/TensorRT-LLM）
  ☐ 跑 HumanEval 基准测试，记录 Pass@1
  ☐ 跑 GSM8K 基准测试，记录准确率
  ☐ 跑 Spider 基准测试，记录准确率

预期结果：
  HumanEval：55-65%（≈ GPT-3.5）
  GSM8K：70-80%
  Spider：60-70%

验证标准：
  ✅ HumanEval ≥ 55% → 继续
  ❌ HumanEval < 45% → 换模型或调参数

交付物：
  - 基准测试报告（含原始数据）
  - 部署文档（环境/步骤/踩坑）
  - 失败题目清单
```

### Step 2：LoRA 进化验证（第 2 周）

```
目标：验证"推理 → 验证 → 训练 → 提升"进化闭环

任务：
  ☐ 用 Step 1 的失败题目构造训练集
  ☐ LoRA 微调（Qwen2.5-Coder-7B + LoRA r=16, alpha=32）
  ☐ 重新跑 HumanEval / GSM8K / Spider
  ☐ 对比前后通过率

预期结果：
  HumanEval 提升 ≥ 5%（从 ~60% → ~65%+）
  GSM8K 提升 ≥ 3%
  Spider 提升 ≥ 3%

验证标准：
  ✅ 提升 ≥ 5% → 闭环成立，进入 Step 3
  ❌ 提升 < 5% → 重新评估进化机制
  ❌ 下降 → 微调流程有问题，排查

交付物：
  - 训练集说明（数据来源/格式/大小）
  - 训练配置（超参数/硬件/耗时）
  - 对比报告（before/after）
```

### Step 3：多节点验证（第 3-4 周）

```
目标：验证多节点聚合是否有增益

任务：
  ☐ 3 个节点独立部署（不同 LoRA 方向）
  ☐ 实现简单的 P2P 调度（不需要链上）
  ☐ 实现结果聚合（多数投票 + 信誉加权）
  ☐ 重新跑基准测试

预期结果：
  聚合后 > 单节点最优

验证标准：
  ✅ 聚合有增益 → dMoE 方向确认
  ❌ 聚合无增益 → 回退单节点服务模式

交付物：
  - 节点部署指南（新节点 30 分钟上线）
  - 调度器实现
  - 聚合策略对比报告
```

### 决策树

```
Step 1 结果：
  HumanEval ≥ 55% ──→ Step 2
  HumanEval < 45% ──→ 换模型（DeepSeek-Coder-7B / CodeLlama-7B）

Step 2 结果：
  提升 ≥ 5% ──→ Step 3（进化闭环成立）
  提升 < 5% ──→ 调整训练策略（更多数据/不同超参/不同微调方法）

Step 3 结果：
  聚合有增益 ──→ 进入正式开发（链上调度 + 代币经济）
  聚合无增益 ──→ 转型：单节点推理服务 + 进化闭环
```

## 🏗️ 架构决策记录（ADR）

### ADR-001：Base 模型选型
- **决策**：Qwen2.5-Coder-7B（INT4 量化）
- **原因**：HumanEval 65% ≈ GPT-3.5，3060 可跑，开源友好
- **替代方案**：DeepSeek-Coder-7B、CodeLlama-7B
- **回退**：如果 Step 1 < 45%，切换到 DeepSeek-Coder-7B

### ADR-002：验证策略
- **决策**：只做可验证任务（代码/数学/SQL）
- **原因**：Agent 场景 70% 可自动验证，覆盖足够
- **替代方案**：人工标注（成本高）、众包标注（质量低）
- **回退**：如果自标注不可靠，引入人类标注者激励

### ADR-003：链下 Router + 链上结算
- **决策**：推理调度链下，费用结算链上
- **原因**：高频推理的 Gas 成本不可接受
- **替代方案**：全链上（太贵）、全链下（不可信）
- **回退**：如果链上结算成本仍高，暂用中心化账本

### ADR-004：协调机制
- **决策**：渐进式去中心化（核心小组 → 精英共和 → 社区自治）
- **原因**：Linux/Apache 的成功路径
- **替代方案**：一上来 DAO 治理（效率低）、完全中心化（违背愿景）
- **回退**：无

### ADR-005：自产自销冷启动
- **决策**：EvoAgent 作为 DecentralAI 第一个节点客户端
- **原因**：保证基本请求量，不依赖外部用户
- **替代方案**：等外部用户（可能永远不来）、补贴激励（不可持续）
- **回退**：如果 EvoAgent 推理质量不满足需求，用 OpenAI 降级
