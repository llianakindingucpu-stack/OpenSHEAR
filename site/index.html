The Problem

Centralized AI is broken

Current AI infrastructure demands uniform, expensive hardware. One broken GPU kills the whole job. One region outage takes down the service. OpenSHEAR changes the rules.

🔗
Centralized AI

Transformer pipelines require KV Cache

Memory grows quadratically with sequence length. Every token depends on all previous tokens. You need massive GPU VRAM just to hold the attention matrix — and it's shared across all workers.

⚡
OpenSHEAR

Linear recurrence: O(1) per token

SHEAR uses RWKV-style time-mix: fixed-size state that never grows. Each token only needs ~3 matrix multiplications. The state is local to each Cell — no synchronization, no contention.

💀
Centralized AI

One node fails → whole job crashes

Pipeline-parallel architectures have a critical path: the slowest shard determines throughput. If one GPU hangs, the entire model waits. Recovery requires checkpoint restart.

🛡️
OpenSHEAR

Remove any Cell, rest keeps working

Cells are fully independent. No shared state, no sequential dependency. A crashed Cell is just ignored — the Aggregator reroutes requests. Preempt any task, use any node.

Mechanism

How OpenSHEAR works

Three layers, zero coupling. Each Cell is a fully independent inference unit. The Aggregator learns which Cell is best for each situation.

01 / Input

Token arrives

Every Cell receives the same token embedding simultaneously. No cross-Cell communication. Each Cell updates its own local state.

parallel · rayon
→
02 / Process

Cells forward in parallel

Each Cell runs its own TimeMix + FFN layers independently. Diversity comes from different sampling temperatures and local state histories.

O(1) per token
⚡
03 / Merge

Aggregator selects best output

Aggregator weighs each Cell's confidence. Not averaging — competitive selection. The strongest Cell's prediction wins.

WeightedSum · BestOfN

Privacy by Architecture

Your prompt is never seen in full by any single node

SHEAR doesn't add encryption as an afterthought. Privacy is built into the inference mechanism. When a prompt enters the network, it's split across multiple cells — no node can reconstruct the original.

✗ Cloud API / Token Relay

Your complete prompt is sent to a single entity. Every word is visible, loggable, and resellable.

  • Full prompt exposed to provider
  • Middleman can silently downgrade models
  • Prompt injection by intermediary layer
  • Data flows into training pools
  • Single point of trust — and failure

✓ SHEAR Network

Prompt is split into task shards. Each cell processes a fragment. No node sees the full picture.

  • No single node sees complete prompt
  • No middleman — peer-to-peer by design
  • Open source — fully auditable pipeline
  • You choose which nodes process your data
  • Privacy scales with network size

Like Tor for AI inference — but without the latency overhead.
Privacy isn't a feature. It's the architecture.

Get Started

From zero to inference in 30 seconds

Build
Interactive Inference
Speculative Mode
Benchmark
# Clone and build
git clone https://github.com/llianakindingucpu-stack/OpenSHEAR.git
cd OpenSHEAR/src-rs/decentral-ai-core
cargo build --release
# Interactive inference
cargo run --release --bin shear -- \
  --model /path/to/rwkv.bin \
  --prompt "Hello, how are you?"
# Speculative decoding with 3 ensemble cells
cargo run --release --bin shear -- \
  --speculative \
  --cells 3 \
  --model /path/to/rwkv.bin \
  --consensus 0.5 \
  --prompt "What is 2+2?"
# HumanEval benchmark (resume-supported)
cargo run --release --bin humaneval -- \
  --model /path/to/rwkv.bin \
  --data /path/to/HumanEval.jsonl \
  --max-tokens 256 \
  --resume   # continue from crash
